Data · 20 minActivity 4 / 7

Telecom Customer Experience: Build a Simple Dashboard

Practice writing a clear data-analysis prompt using a realistic telecom customer-support scenario. No coding experience required.

Starting prompt
Analyze this data.

Scenario: Etisalat Customer Support (Simulation)

Imagine you are supporting the customer experience team at Etisalat. Customers contact support about mobile coverage, home internet, billing, SIM activation, plan changes, and roaming. A manager wants to understand which issues are most common, how many tickets remain unresolved, how quickly resolved cases are handled, and how satisfied customers are.

The CSV contains 100 fictional telecom support tickets with dates, regions, service plans, issue categories, contact channels, statuses, resolution hours, service targets, and optional satisfaction ratings. No data rows are shown on this page.

This is synthetic training data created for this workshop. It is not an actual Etisalat or e& dataset and does not represent the company's performance. The CSV is embedded in this HTML and downloads without needing a second file.

Individual tasks

  1. Download the CSV and upload it to an AI tool that supports file analysis.
  2. Test the weak prompt: Analyze this data. Notice what is missing.
  3. Write a better prompt using the five prompt rules: Role, Task, Context, Constraints, Output Format.
  4. Ask for four KPIs: total tickets, number of unresolved tickets, average resolution hours for resolved tickets only, and average customer satisfaction among rated tickets.
  5. Request two charts: a bar chart of ticket counts by issue category and a chart showing the number of tickets by status.
  6. Request a one-page management dashboard with KPI cards, both charts, and two practical improvement recommendations. If the AI tool cannot create a working dashboard, ask for a clear dashboard outline instead.
  7. Verify the total is 100 tickets. Ask AI to ignore blank resolution hours and satisfaction scores when calculating averages, and to compare resolution times with targets only for resolved tickets.
